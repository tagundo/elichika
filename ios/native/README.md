# Native unified iOS host

The device host is a framework loaded into the existing SIFAS process. It does not define `UIApplicationMain`, create another Unity runtime, or run a server executable. All code is compiled ahead of time; the host performs Objective-C method replacement and writes its own state, rather than modifying executable memory.

`SIFASProfile.h` pins the GL/Local and JP 3.12.0 main-image UUID, `UnityAppController.startUnity:` RVA, and first 32 bytes. Packaging separately pins the complete source IPA. The host checks the method ABI and owning main image before releasing the captured method. An unsupported profile with a compatible selector remains held and displays an error. Missing/incompatible methods are rejected, and packaging must refuse such source IPAs.

The gate leaves the existing `application:didFinishLaunchingWithOptions:`/KJP delegate chain and `llas-patcher` endpoint/RSA initialization in place. `startUnity:` is captured without calling its original implementation; setup runs on a worker, while UIKit remains responsive. The original is called once on the main thread only after the aggregate Python runtime status confirms real Go readiness and both advertised tools listeners. This is deliberately different from UnityFramework-based hosting.

Before the existing delegate hook runs, the host validates the actual bundled `payload/publickey.pem`, converts its bounded DER RSA modulus/exponent into the XML format that `llas-patcher` expects, and checks the game's actual initialized string capacity. It saves a previous external `ServerEndpoint`/different `RSAKey` under app-private backup keys and selects `127.0.0.1:8080` plus that public key. Missing/malformed/oversized keys keep startup held; no account credentials are changed. The Go/Python layer must also validate writable server keys against these bundled resources before readiness, preserving existing files on mismatch.

`ElichikaPythonRuntime.mm` owns one persistent native thread and one CPython 3.13 interpreter. It uses isolated configuration, app-local module paths, no environment/site imports or signal handlers, and explicit GIL save/restore between control operations. Python serving/job threads remain Python-owned. The interpreter is never finalized or rebound to a different payload root.

The built-in `_elichika_ios` exposes the Go JSON ABI in `ElichikaServerBridge.h`, progress events, OS-trusted bounded HTTPS, streamed atomic downloads, and document import/export. Document UI runs on main while file copies and waiting happen off main; imports are copied into app-private storage under a fresh identifier. HTTPS uses normal system trust, has size/time limits, rejects downgrades, and strips credentials on cross-host redirects.

Native configuration explicitly puts server payload/databases in `Library/Application Support/Elichika/data`, downloadable packs in `Documents/Elichika/packs`, and picker imports in `Documents/Elichika/imports`. Documents directories are created with canonical containment checks; existing data and custom cache preferences are not copied or removed. With the app's Files/Finder sharing flags, large packs can be placed directly in the packs folder. Picker import remains an optional copy operation. The simulator probe checks the actual configured paths and directory existence without publishing container paths.

External asset libraries use the exact picker URL's access grant before any directory metadata or file operation. Select the parent library containing `packs`, rather than `packs` itself. Bookmark data and its resolution mode are stored together; older untagged bookmarks remain readable. Catalyst first requests an explicit security-scoped bookmark. Ordinary PlayCover signing may omit the entitlement required for that persistent bookmark, so the host can retain an implicit scope valid within the current macOS boot and clearly labels its lifetime. After a reboot or revoked permission, the startup panel offers direct folder reselection without deleting the previous library. The active library remains leased until process exit; selecting a different library changes only the next-launch path. Server databases remain in app-private storage. The Foundation regression harness tests grant ordering, bookmark modes and rollback with a scoped-URL fixture; it does not prove real PlayCover picker or entitlement behavior.

Accounts, server administration, and tools open in an app-owned WKWebView restricted to the currently owned loopback listeners. Private web capability and public readiness nonce are independently generated. Diagnostics omit both tokens and panel URLs. The upper-right Elichika button is visible on first launch; Hide/Show button in the management panel persists its own preference. A non-cancelling one-finger two-second hold in the game window's upper-right corner reopens the combined server and game menu even while hidden. It allows simultaneous recognition and does not delay ordinary touches. Wide windows use a Mac-style sidebar; narrow windows use a compact destination picker. Destinations reuse four retained WebKit documents, so switching between server/app settings or asset tools/3D does not reload those documents. The game settings entry reuses the original dated client's FOV and orientation sheets and its existing fast-intro preferences. A delayed Objective-C bridge validates the API and captures the actual initialized client controller from its original poll. That poll continues applying preferences; only its exact old button and delegated long-press are suppressed. Cached controls are rediscovered only when the original client reparents them to another root view. Original client dylibs and standalone behavior are unchanged. The Simulator-only fake-client proof verifies UIKit routing and retained navigation, not actual Unity FOV or physical touch recognition; game/device validation remains separate.

The actual management WebView uses WebKit's default persistent data store. Python admin/tools origins stay fixed at `127.0.0.1:8772` and `127.0.0.1:8770`, so tool visibility/order preferences retain their localStorage origin across app restarts. Authentication capabilities remain newly generated each launch; the host never manually stores them. A Simulator-only helper navigates this same management WebView to both real authenticated pages, seeds a non-sensitive test key on the first process launch, and verifies the prior value before any write on the second. Its bounded callbacks emit only booleans and public port numbers. Core-only probes do not claim this check.

Background/foreground and memory-pressure events are sent to Python. No indefinite background-server execution is claimed. On return, actual backend status is polled before considering recovery; backend recovery never invokes Unity startup twice. Startup failures stay visible with the original game call held.

The experimental Archive-pending device channel is explicit and separate from ordinary startup. Native configuration sets `experimental_device` only after matching the signed Info channel/status/source pin, the signed capability's full device-runtime flags and exact pending Archive state, and the actual 217-byte source configuration SHA-256. Inconsistent markers fail startup; environment variables, preferences, and Simulator flags cannot enable the channel. The panel identifies pending Archive publication and device validation, with direct Files packs placement guidance. Local server/tools readiness is still required and is not a claim that Archive publication finished.

`tests/HostCoreTests.cpp` exercises the pure policy: readiness/capture order, foreground gating, duplicate calls, failures, recovery, and stale-generation rejection. Build with a C++17 compiler. `tests/SimulatorProbe.mm` is compiled only with `ELICHIKA_SIMULATOR_PROBE=1` into an independent test application. It supplies a fake game entry while running real Go/Python/payload initialization and authenticated Go health. Its evidence identifies the fake-game boundary and any explicitly requested `--elichika-core-probe` mode; neither fake game nor that flag is compiled into the device framework.

Successful compilation or this simulator probe does not establish physical iPhone/iPad gameplay, background behavior, or full editing-tool parity. Those require exact-artifact device validation.

The preserved dated client source uses `SIFASFOVMinimum=0.75`, `SIFASFOVMaximum=1.0`, `SIFASFastIntro=NO`, and `SIFASOrientation=0` as its defaults. Game-view reset changes only these four preferences. It does not reset connection credentials, user data, asset paths, or either standalone overlay preference.

# Shared authored-scale board: original-game scene QA

This branch's workflow explicitly uses `--preview-only`: initial HOME, the
selected costume preview, and final HOME, with two native snapshots per case.
Its separate `audit_preview.py` cannot claim an MV or full seven-case pass.
The four MV cases captured by run42396817217/source28368ae remain independent
evidence from another PID; that run's incomplete seven-case verdict is retained.
The original full-flow mode and its strict auditor remain available unchanged.

This manual-only isolated workflow uses the unchanged public Android GL3.12
player and frozen signed tutorial provider7.1. No application, native method,
PlayerPrefs, personal account or production branch is changed.

The candidate writes the saved NodeScaling target D into the two corresponding
authored Transform.localScale values. All existing Node records, animation,
mesh, texture and physics data are preserved. One board resource/pack is used
by both the costume base/HOME route and view1/MV route. View2 uses the bare
model. Separate private CAB identities prevent candidate/control bundle cache
collisions. Node-only and stock original controls are independently published
to fresh provider databases before any account exists.

The original game creates one disposable account normally. Its main tutorial99
and four completed guides must already be present before any fixture API is
called. Only the existing story/theme/favorite/custom-MV-deck normal endpoints
prepare Rina209 plus eight distinct stock members. There are no direct SQL writes
to account data and no forced game callbacks, scene jumps or scale operations.

Fresh typed UI controls drive the proven default live10001 route. Required
checkpoints are initial HOME, actual selected costume preview, candidate board
MV, candidate bare MV, Node-only board MV, original board MV and final HOME.
Each checkpoint links two read-only native snapshots at least five seconds
apart to the actual selected IDs and fresh typed UI. The original passive
observer and Spawn identity binding are unchanged from ef49a4f8.

The new auditor checks absolute D rather than D squared, finite local/world TRS,
unit rotations, actual bone motion across the two MV snapshots, normal start
routes, and initialized spring caches consistent with their own actual world
endpoints. It does not require an edited model to retain a control's old S0
cached spring length. Pose/motion/physics trajectory equivalence across every
frame is not claimed. The original frozen scene reports and the separate
Animation111 rejection experiment remain unchanged.

Every model and manifest is hash bound. Actual Unity/scene evidence is required
for a pass; local synthetic tests, screenshots alone, API success or observer
startup are not runtime success. iOS files are statically preserved inputs;
this workflow makes no iOS execution or production-release claim.

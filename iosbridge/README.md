# In-process game service

Build `./cmd/elichika_ios_carchive` with `-tags elichika_inprocess -buildmode=c-archive` and cgo enabled for the selected iOS SDK. The generated header exports `ElichikaServerStart`, `ElichikaServerStatus`, `ElichikaServerStop`, `ElichikaServerCommand`, and `ElichikaServerFree`. Each returned string is separately allocated and must be released using `ElichikaServerFree`. Inputs are copied and never modified.

Start accepts the options defined in `ios/CONTRACT.json`. The host must install the complete prepared payload into an absolute writable `data_root` before starting. The library does not copy a payload, change the process working directory, register application signal handlers, launch executables, or exit the application. It defers configuration, migrations, SQLite engines, localized game data, and image/form caches until Start. Startup errors are returned in Status instead of deliberately panicking the host. When `resources_root` is supplied, startup also checks that the writable RSA pair is valid and its public key matches the bundled client key; a mismatch fails before the listener opens.

Start and Stop return promptly. Poll `state`; readiness is established only after real game routes/data initialize, the owned loopback listener binds, and its authenticated health endpoint answers an actual HTTP request. `state=ready`, `phase=running`, `ready=true`, and `endpoint` identify that point. `generation` advances on accepted Start/Command and on every explicit Stop, including Stop while already stopped, so a tool can detect a later user stop before auto-resuming.

Stop remains `stopping` while active requests drain. Only after every handler returns does it close database engines and release `.database-maintenance.lock`. Tools must wait for `state=stopped` and no running job before acquiring the Python maintenance guard or mutating database files. A subsequent Start reopens the databases and rebuilds data/asset/form/subsystem caches. The library intentionally does not terminate active handlers and close their databases underneath them.

The same database-maintenance lock is held throughout initialization, serving, and Go maintenance jobs. A Python tool's `begin_job` must stop/drain Go before taking its own guard. Its `finish_job` must release that guard before an optional Start. This ordering prevents both deadlocks and writes racing the game server.

Commands are JSON objects containing `command`. Supported commands are `status`, `start` (with `options`), `stop`, `management_request`, `config_read`, `config_save`, `cdn_cache`, `reload`, `rebuild_assets`, `fix_training_trees`, and `reset_accounts`. Maintenance commands require a previously configured, stopped service and return an asynchronous `job`. Poll until `job.state=succeeded|failed`; failures carry an explicit error. `config_save` takes a partial `config` object and preserves omitted settings. `cdn_cache` requires an `enabled` boolean. Unknown commands fail explicitly. Archive/CDN download orchestration remains with the existing Python job implementation; the ABI does not silently simulate those commands.

`management_request` invokes the existing restricted management router, rather than spawning another Go process. It accepts `method=GET|POST`, a local `/webui/admin/...` or `/webui/user/...` `path`, and optional `body`/`content_type`. A body object maps string keys to multipart form string values; a string body is copied verbatim. The job result contains `status`, `headers`, and text `body`, capped at 8 MiB. Legacy build-and-launch Alisa routes are excluded. The game HTTP listener retains the real game, live/MV, account, pack, and WebUI handlers.

Run focused Linux lifecycle tests using `go test -p 1 -tags elichika_inprocess ./runtimeinit ./iosbridge`. These exercise explicit initialization, failure cleanup, actual loopback HTTP readiness, active-request drain, stop-during-start, reload, strict options, and unchanged working directory. They do not establish iOS device game compatibility; the iOS SDK builds and real game/protocol probes are separate gates.

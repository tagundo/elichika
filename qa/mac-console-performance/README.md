# Actual Mac Console comparison

`mac-console-performance.yml` builds C3 and the hash-bound C5 candidate on the same Apple Silicon macOS 15 runner. For these QA-only harness revisions, it verifies the exact seven C5 source hashes and complete nine-file SwiftPM source set and reuses the cryptographically bound artifact from an actual matching fresh 45-test native pass including the persistent wrapped-log regression. The normal C5 application workflow still runs its mandatory full suite. The AppKit probe hosts the complete production `RootView` and `AppModel` in a real visible window. Its temporary source projection removes exactly the application's `@main` annotation; it changes no view, polling or logging implementation.

The authenticated local fixture returns an explicitly controlled `server_running` state. It executes the exact `LogBuffer` class extracted from each corresponding Python source. This isolates native UI and bridge logging costs. It does not represent a complete bundled application launch, Go server, game login, Internet/CDN throughput, or a user's real library.

The 24 paired cases cover 0/500/1500 initial resident lines, Console visible/hidden, steady idle/bulk, and baseline/candidate. Every measurement lasts eight seconds. Bulk cases transfer eight parallel, paced 64 MiB HTTP responses through loopback and verify every received byte with SHA-256, while ingesting 250 synthetic Unicode log lines per second. Idle cases retain their initial document without new logs. All native polling goes through the production `URLSession` and `AppModel.refresh()` every 700 ms.

Reports include process CPU deltas, peak RSS, main-queue dispatch latency, model/leaf publication counts, hosting view layout/draw counts, protocol response sizes, throughput, and hashes. Python CPU covers the controlled HTTP fixture, exact production LogBuffer and eight download/hash client threads together. It does not isolate the shipped bridge process. CPU percentages are fractions of one core, so they may exceed 100%. Paired results are single controlled samples and should be read with that sampling limit. A baseline/patched diagnostic pair must pass before the full 24-case matrix starts.

After timing, the patched probe uses the actual `NSTextView`: it selects and copies an existing middle line, scrolls back, applies two synchronous append batches which SwiftUI can coalesce and which remove 80 old lines, and checks selection, copied text, visible anchor and bottom-following. A missing document or failed assertion fails that case. Raw ready files, capabilities, and process output stay private and are removed before artifact export. Source receipts, compiler failures and measured results remain reviewable even when a later case fails.

Local Python checks exercise syntax, authentication, and the extracted class only. Runtime measurements require the actual Mac workflow and are never inferred from those checks.

Cold backlog preparation has a predeclared 120-second bound for both variants and a separate `cold-readiness.json` receipt measured from native process launch. It is excluded from the steady-state CPU window. After the empty baseline/candidate diagnostic passes, a 1500-line visible backlog diagnostic requires the candidate to complete all native checks and records an old-baseline bounded timeout honestly. The full matrix then attempts every planned case, including candidates paired with a baseline timeout. A timeout has no completed CPU value; any partial native-stage record remains diagnostic evidence only. The matrix gate requires all 12 candidate cases, verified download bytes, actual polling, no visible runtime error, and strict native document postchecks. Only a dedicated native-marker wait timeout is accepted as an old-baseline timeout outcome; socket, download, future and unknown failures fail the gate. A matrix with any old-baseline timeout is explicitly labelled `CANDIDATE_CASES_PASS_WITH_BASELINE_TIMEOUT_OUTCOMES`, never all-24-pass. Target CPU windows are eight seconds; actual elapsed windows and separate launch-to-ready wall times are recorded.

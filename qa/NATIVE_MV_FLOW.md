# Disposable GL MV evidence flow

This is QA-only source. It never changes an APK, game callback, player-data field,
main branch, release, or production application. The fixture is built from the
exact frozen source in frozen-fixtures.json, with its normal VCS/build information
retained. No prior Go binary hash is forced onto a new source revision.

The initial language, Title, Terms, Light download, completion and native Home
candidate use fresh OCR/current native Surface geometry. Download confirmation
requires both current alternatives, exactly one orange Light radio and the visible
unselected Full annulus. Two fresh matching observations precede each input.
Post-scroll/selected-Light/completion/Home rules remain runtime-unverified until
actual execution. UI MB estimates, stored cache bytes, and aggregate interface
counters have separate labels.

No Frida server/observer starts before the settled native Home candidate and real
bootstrap. Native engine-loop stack, PID/start ticks and UnityMain comm establish
the actual main TID. Deferred managed initialization asserts that TID first. The
first observer RPC failure is retained, never retried; logs/native evidence precede
owned-game stop and script cleanup.

Navigation advances on actual Home/member scenes. The existing MVDriver proves
same/different costumes, all12 independent instances, fresh successful live-start
requests, decoded playback videos, and complete deck restoration/reopening. The
client suit catalog is read twice before the FIRST edit and after restoration;
the actual view must bind the exact complete source array. Raw multiplicities,
including preexisting entries, are preserved. Server DB row counts are separate.

After these MV gates, ordinary native FovSettingsActivity changes the live camera
clamps/orientation. No managed RPC spans Unity pause. Old scripts remain quiescent
until game stop; a fresh native-TID-bound script reads each resumed live scene.
FOV requires the matched enabled on-screen camera's actual scalar getter effect
and its own2.0/0.5 corrections, using candidate-bound source arithmetic. Unobserved
native/intro flags stay false. Any successful focus status still requires final
per-feature evidence review and is never a blanket client/release approval.
